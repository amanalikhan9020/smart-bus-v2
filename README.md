# SmartBus Astana

Учебный прототип выбора поездки по **симулированной** загруженности автобуса. HTML, CSS и JavaScript; сервер приложения, платное API и физические датчики не нужны.

## Запуск

Из корня репозитория:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Откройте локальный адрес сервера в обычном браузере. Для регистрации с Web Crypto используйте localhost/loopback или HTTPS, а не открытие HTML через `file:`. В облачной среде проверяйте сервер локальными запросами; создание публичного preview не требуется.

Зависимости для самого сайта отсутствуют. Данные принадлежат origin браузера: смена порта, профиля, протокола или очистка localStorage создаёт отдельное хранилище. Данные переживают перезагрузку страницы и перезапуск сервера при сохранённом origin и профиле.

## Основной сценарий

1. Продолжить как гость или зарегистрироваться/войти.
2. Выбрать маршрут, остановку и время.
3. Получить прогноз и сравнить варианты отправления: выбранное время, +30 и +60 минут.
4. Выбрать вариант и сохранить именно его.
5. Открыть Saved Trips, перезагрузить страницу и найти поездку; доступны фильтр и удаление.
6. Посмотреть среднюю/максимальную загрузку и диаграмму сохранённых поездок. После добавления и удаления данные пересчитываются.

Варианты сравнения обозначают моменты для расчёта, а не реальное расписание автобусов. Одинаковые прогнозы допустимы. Переход через полночь отмечается как следующий день.

## Проверки

Проверка синтаксиса из корня репозитория:

```sh
node --check script.js
node --check storage.js
node --check model.js
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Браузерные проверки и их фактический результат описаны в [чек-листе Endterm](docs/ENDTERM.md#результаты-проверок); детали запуска — в [tests/README.md](tests/README.md). В этой среде имеются Python Playwright и системный Chromium. Инструкция проверки не заменяет запуск тестов: раздел результатов явно различает выполненные и ожидающие проверки.

## Ограничения и незавершённые пункты

- Прогноз задаётся правилами спроса; это не машинное обучение, не live CTS и не гарантия времени прибытия.
- Аккаунты и поездки локальные, синхронизации и серверной авторизации нет. Получение хеша пароля через PBKDF2 не шифрует localStorage и не защищает от владельца браузера.
- Обычные старые пароли автоматически мигрируют в PBKDF2 с сохранением ID и поездок. Для старого пустого/пробельного пароля требуется явная замена через локальную форму восстановления. Это исправление слабой старой записи в текущем браузере, не защищённый удалённый сброс пароля.
- Безопасный вывод текста защищает от исполнения HTML в отображаемых значениях; он не превращает статический прототип в защищённый серверный продукт.
- Результаты двух реальных пользователей вне команды и два улучшения именно по их feedback ещё не предоставлены. Автоматические тесты и исправления по аудиту их не заменяют.
