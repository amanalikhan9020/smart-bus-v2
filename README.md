# SmartBus Astana

Учебный прототип выбора поездки по **симулированной** загруженности автобуса. HTML, CSS и JavaScript; сервер приложения, платное API и физические датчики не нужны.

## Запуск

Из корня репозитория:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Откройте локальный адрес сервера в обычном браузере. Для регистрации с Web Crypto используйте localhost/loopback или HTTPS, а не открытие HTML через `file:`. В облачной среде проверяйте сервер локальными запросами; создание публичного preview не требуется.

Сборка и установка пакетов для запуска сайта не нужны. Файл `.nojekyll` сохраняет публикацию GitHub Pages как статического сайта без обработки Jekyll. Leaflet 1.9.4 хранится локально в `vendor/leaflet`; фоновые тайлы OpenStreetMap загружаются из Интернета. Данные принадлежат origin браузера: смена порта, профиля, протокола или очистка localStorage создаёт отдельное хранилище. Данные переживают перезагрузку страницы и перезапуск сервера при сохранённом origin и профиле.

## Основной сценарий

1. Продолжить как гость или зарегистрироваться/войти.
2. Выбрать маршрут, остановку в списке или на карте и время.
3. Получить прогноз и сравнить варианты отправления: выбранное время, +30 и +60 минут.
4. Выбрать вариант и сохранить именно его.
5. Открыть Saved Trips, перезагрузить страницу и найти поездку; доступны фильтр и удаление.
6. Посмотреть среднюю/максимальную загрузку и диаграмму сохранённых поездок. После добавления и удаления данные пересчитываются.

Варианты сравнения обозначают моменты для расчёта, а не реальное расписание автобусов. Одинаковые прогнозы допустимы. Переход через полночь отмечается как следующий день.

## Карта и изменение времени

Кнопка «Open stop map» открывает карту. На ней показана **201 остановка с координатами из опубликованного GTFS-набора**, сохранённого в [`data/astana-stops.json`](data/astana-stops.json). Пронумерованные маркеры сопоставленных остановок связаны со списком и прогнозом: выбор маркера меняет остановку, а выбор в списке выделяет её на карте. Для остановки без подтверждённого соответствия интерфейс прямо сообщает, что местоположение не найдено; выдуманная точка не добавляется. Линии маршрутов и интерполированные координаты удалены.

Источник: Mansurova et al. (2025), DOI [10.3390/data10080119](https://doi.org/10.3390/data10080119), открытый репозиторий [kabuli-web/bus-eta-uncertainty](https://github.com/kabuli-web/bus-eta-uncertainty). Данные относятся к историческому набору за **29 июля — 21 сентября 2024 года**. Указание CC BY 4.0 взято из атрибуции побайтово совпадающего зеркала; первичная страница лицензии недоступна из среды проверки. Ссылки, происхождение и сопоставления записаны в [аудите источников](docs/STOP_DATA_SOURCES.md).

С текущими списками приложения сопоставлены 35 из 36 остановок Bus 10, 5 из 18 Bus 501, 3 из 10 Bus 40 и 2 из 11 Bus 53. Для 501/40/53 это соответствия названиям физических остановок; обслуживание этих остановок указанными маршрутами источник не подтверждает. Это исторические координаты, без live-трекинга и подтверждённых трасс CTS. Прогноз загруженности остаётся симуляцией.

Время меняется через отдельные списки **Hour / Minute**, обычное текстовое поле `HH:MM`, ползунок и кнопки −15/+15 минут. Системное окно выбора времени не требуется. «Now» устанавливает текущее время Астаны (`Asia/Almaty`). Прогноз и варианты сравнения обновляются сразу. Кнопки меняют часы циклически через полночь; календарная дата не выбирается. Сравнение +30/+60 минут отдельно отмечает следующий день при переходе через полночь.

Для подложки используется OpenStreetMap с атрибуцией на карте. API-ключ и backend не нужны: координаты загружаются из локального JSON сайта. Если внешние тайлы недоступны, остаются нейтральная координатная сетка и реальные точки источника; это не схема города с выдуманными объектами. Состояние загрузки поясняет сообщение карты, предусмотрена повторная загрузка данных. Leaflet распространяется по BSD-2-Clause: лицензия и проверенный SHA-512 исходного npm-пакета указаны в `vendor/leaflet/LICENSE` и `vendor/leaflet/PROVENANCE.txt`.

`compat.js` создаёт ID с запасным вариантом через `crypto.getRandomValues`, если `crypto.randomUUID` недоступен. Вызовы `Object.hasOwn` и `Array.at` заменены совместимыми операциями. У JS/CSS указан параметр версии `v=20261106.2`, чтобы браузер загрузил согласованный комплект файлов после обновления.

## Проверки

Проверка синтаксиса из корня репозитория:

```sh
node --check compat.js
node --check script.js
node --check storage.js
node --check model.js
node --check map-data.js
node --check route-map.js
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Браузерные проверки и их фактический результат описаны в [чек-листе Endterm](docs/ENDTERM.md#результаты-проверок); детали запуска — в [tests/README.md](tests/README.md). В этой среде имеются Python Playwright и системный Chromium. Инструкция проверки не заменяет запуск тестов: раздел результатов явно различает выполненные и ожидающие проверки.

Текущая версия прошла **36 браузерных тестов за 94,458 секунды, OK (exit 0)**: 19 прежних сценариев, 9 обновлённых проверок карты/времени и 8 новых проверок исправления. Подтверждены 201 исходная точка, неполное покрытие маршрутов, отказ тайлов и повтор загрузки JSON, Hour / Minute и текстовый HH:MM, сохранение выбранных 19:30, совместимость без новых API, версии ресурсов, карта с главного экрана и мобильный экран 320px/390px.

Исторический результат прежней демонстрационной карты — 28 тестов за 59,566 секунды. В PDF остаётся более ранний результат: 19 тестов за 33,690 секунды; презентации при текущем исправлении сайта не пересобирались. Автоматические проверки не заменяют тестирование двух реальных людей.

## Ограничения и незавершённые пункты

- Карта использует 201 историческую точку GTFS. Для части остановок приложения соответствие не найдено; принадлежность остановок маршрутам 501/40/53 не подтверждена. Официальных трасс и live-данных нет. При отказе OpenStreetMap реальные точки остаются на нейтральной сетке.
- Прогноз задаётся правилами спроса; это не машинное обучение, не live CTS и не гарантия времени прибытия.
- Аккаунты и поездки локальные, синхронизации и серверной авторизации нет. Получение хеша пароля через PBKDF2 не шифрует localStorage и не защищает от владельца браузера.
- Обычные старые пароли автоматически мигрируют в PBKDF2 с сохранением ID и поездок. Для старого пустого/пробельного пароля требуется явная замена через локальную форму восстановления. Это исправление слабой старой записи в текущем браузере, не защищённый удалённый сброс пароля.
- Безопасный вывод текста защищает от исполнения HTML в отображаемых значениях; он не превращает статический прототип в защищённый серверный продукт.
- Результаты двух реальных пользователей вне команды и два улучшения именно по их feedback ещё не предоставлены. Автоматические тесты и исправления по аудиту их не заменяют.
